## 추가 자료 넣기

새 엑셀·PDF·이미지는 **materials/incoming/**에 넣고 AI에게 파일명을 알려준다. 기존 원본에 덮어쓰지 않고 새 버전임을 표시한다.

AI는 내용을 확인한 뒤 원본 보관 위치, 사이트용 데이터, 지도안 연결과 자료 목록을 갱신한다. 사용자가 원본을 수동으로 웹 배포 폴더에 복사할 필요는 없다.

원본 자료는 로컬 `materials/`에 보관하고 Git에서 제외한다. 원본 파일 자체는 Git 이력에 저장되지 않으므로 이 폴더까지 포함해 프로젝트를 보관한다. 사이트 배포에는 `dist/`만 사용하며, 원본 엑셀·HWP를 통째로 게시하지 않는다.

## 미제공 자료 표시 — 확정 규칙

- 텍스트: **자료 업로드 예정입니다.**
- PDF: 실제 뷰어와 같은 크기의 **회색 박스** 안에 **자료 업로드 예정**.
- 이 문구는 파일 업로드 기능을 뜻하지 않는다.
- 파일이 있는데 읽기 실패한 상황은 미제공 자료와 구분한다.

## Firebase 연결

3단계의 대상은 `as-open-class`이며 신청 함수 배포·공유·실제 시험 저장 검증을 마쳤다. 다음은 작업 순서 문서의 7단계 교차 검토다. Hosting 배포·QR은 8단계다. 로컬 개발·preview는 실제 프로젝트 ID일 때 배포된 서버에 연결하며, `REGISTRATIONS_EMULATOR=true` 또는 `demo-` 프로젝트는 로컬 에뮬레이터를 사용한다. 서버용 환경변수 예시는 `functions/.env.example`, 실제 주소·실행 계정과 API 계약은 [신청 저장 연결](<docs/신청 저장 연결.md>)에 있다.

사이트에는 AI API 호출이 필요하지 않다. GPT와 Claude는 개발할 때 사용하는 도구다.
