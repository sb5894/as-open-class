# 수업 데이터 변환과 확인 방법

1단계는 수업·공간 데이터와 자료 연결을 준비한다. 전체 지도·신청·배포는 이후 단계다.

2026-10-20 이후 기본 변환은 최초 엑셀에 `materials/original/curriculum/1020-additions/2026 공개보고회 준비(공개수업, 예산).xlsx`의 최신 교육 내용을 덧붙인다. 새로 작성되거나 달라진 반별 내용과 1학년 공통 문구를 적용하고, 새 빈 셀은 기존 내용을 지우지 않는다. 공개 여부/장소는 별도 확정 규칙을 유지하며 예산 항목은 읽지 않는다. PDF 10개는 `scripts/data_rules.py`의 명시된 학급 집합으로만 연결한다. 새 원본도 같은 상대 경로로 보관해야 재변환이 일치한다.

## 실행

Node/npm 외에 `uv`가 필요하다. 현재 개발 PC에서 실행을 확인했다. `uv`가 변환에 필요한 Python과 openpyxl을 준비한다. 의존성은 `scripts/convert_data.py`와 그 옆 `.lock` 파일에 고정했다.

2026-10-19 현재 세션에는 `uv`가 PATH에 없어, 프로젝트 `.venv`에 openpyxl 3.1.5를 설치해 같은 스크립트를 직접 실행했다. `& ./.venv/Scripts/python.exe scripts/convert_data.py`로 재생성하고 `--test`, `--check`로 검증할 수 있다. 전역 Python 패키지는 변경하지 않았다.

**실행 전제:** `materials/original/`의 엑셀·도면·PDF가 로컬에 있어야 한다. 이 폴더는 `.gitignore`로 제외되므로 Git 저장소만 새로 받아서는 원본이 함께 오지 않는다. 원본 자료를 같은 상대 경로로 별도 복사해야 한다. `data:convert`, `data:check`, `npm test`의 Python 테스트는 원본에 의존하며, 원본이나 `uv`가 없으면 실패한다. `npm ci`만으로 이 조건이 갖춰지지는 않는다. 첫 `uv` 실행에는 Python/패키지 다운로드가 필요할 수 있다.

프로젝트 루트 PowerShell에서 실행한다.

```powershell
npm.cmd run data:convert
npm.cmd run data:check
npm.cmd test
npm.cmd run check
npm.cmd run build
npm.cmd run verify:sources
```

- `data:convert`: 원본을 읽어 JSON·검토표·선택된 공개용 PDF 복사본을 생성한다.
- `data:check`: 같은 입력으로 재변환한 결과와 현재 생성 파일을 바이트 단위로 비교한다. 파일을 쓰지 않는다.
- `test`: Python 변환 테스트와 TypeScript 조회 테스트를 실행한다. 임시 엑셀에서 값 변경·행 삽입·날짜 저장 방식 변경·잘못된 자료를 확인한다.
- `verify:sources`: 원본 기록에 등록한 20개 파일의 크기·해시가 그대로인지 확인한다.

## 새 엑셀 적용

1. 새 버전은 기존 원본에 덮어쓰지 않고 `materials/incoming/`에 넣는다.
2. 다음과 같이 파일명을 지정한다. 아래 이름은 사용 예시이며 실제 파일명으로 바꾼다.

```powershell
npm.cmd run data:convert -- --workbook "materials/incoming/새 수업정보.xlsx"
npm.cmd run data:check -- --workbook "materials/incoming/새 수업정보.xlsx"
npm.cmd test
npm.cmd run check
npm.cmd run build
```

3. [수업 연결표](<수업 연결표.md>)와 [누락 자료](<누락 자료.md>)를 확인한다. 새 버전의 보관 위치·적용 여부를 [자료 목록](<자료 목록.md>)에 기록한다.

`--workbook`을 생략하면 최초 엑셀을 사용한다. 새 버전 검사에도 같은 경로를 지정해야 한다. 향후 기본 입력을 바꾸려면 `scripts/convert_data.py`의 `DEFAULT_WORKBOOK`을 변경하고 최초 원본 기반 테스트의 기대값도 검토한다.

동일한 두 시트명과 A~G열 의미를 유지하는 양식을 지원한다. 행 번호를 고정하지 않아 학급 행 추가나 이동을 처리한다. 학급·장소 자체가 달라지거나 시트/열 구조가 바뀌면 규칙을 검토해야 한다. 자동으로 장소를 추측하지 않는다.

## 파일 역할

| 파일 | 내용 |
|---|---|
| `scripts/convert_data.py` | 읽기 전용 엑셀 해석, 검증, JSON·표·PDF 복사본 생성 |
| `scripts/data_rules.py` | 도면과 결정 기록에서 확인한 건물·공간, 별도 수업, 공개 범위, PDF 연결 규칙 |
| `src/data/catalog.generated.json` | 사이트에서 사용할 변환 결과. 직접 수정하면 다음 변환에서 덮어씀 |
| `functions/src/data/registration-lessons.generated.json` | 같은 원본에서 생성한 서버용 공개수업 ID·표시 이름. 원본 경로·수업 설명 없이 신청 검증에 필요한 값만 포함 |
| `src/data/catalog.ts` | 데이터 타입과 공개 목록·실제 공간별 수업·원래 교실의 이동 대상 조회 |
| `public/pdfs/*.pdf` | 연결이 확인된 원본 PDF 4개의 동일한 복사본 |
| `docs/수업 연결표.md` | 학급·주제·실제 장소·PDF·근거 행을 사람이 검토하는 표 |
| `docs/누락 자료.md` | 수업별 누락 항목과 원문 확인 사항 |

원본 엑셀·도면·지도안은 수정하거나 다시 저장하지 않는다. 변환이 실패하면 출력 파일을 쓰기 전에 중단한다. `sources`에 입력 경로와 SHA-256을 기록하며, 날짜·현재 시각을 덧붙이지 않아 같은 입력의 재변환 결과가 같다.

PDF 추가·교체는 내용을 확인한 뒤 `PDF_RULES`의 파일명과 학급 대상을 명시한다. 별도 지도안 ID는 `special-1-3`, `special-3-1`, `special-4-5`, `special-6-1`을 사용하고 각 학급만 대상으로 지정한다. 같은 학년이라는 이유로 PDF를 자동 연결하지 않는다. 규칙의 원본 파일이 없으면 PDF 연결을 `null`로 만들고 누락 목록에 기록한다. 과거 생성된 공개용 PDF가 더 이상 쓰이지 않으면 해당 복사본의 제거도 자료 교체 단계에서 확인한다.

## 데이터 의미

- `classes`: 학급/공동 수업 그룹. `homeSpaceIds`는 원래 교실이며 `isPublic`으로 공개 대상을 구분한다. 5-1과 유치원은 공간·학급·비공개 상태만 남는다.
- `lessons`: 공개수업 28개. `classId`로 학급, `spaceIds`로 실제 참관 장소에 연결한다. 신청 선택지와 안내도에서 이 목록을 함께 사용한다. 유치원은 사용자 확정으로 제외했다.
- `locationStatus`: `confirmed`는 결정 기록의 장소를 반영했다는 뜻이다. `provisional` 타입은 가안 장소용이며 현재 공개수업에 유치원 가안은 없다.
- `spaces`: 도면에 근거한 관련 공간 37개. `planLabel`은 원래 도면 표기, `subdivision`은 한국어교실의 4등분이다. `planPosition`은 북/남쪽과 포함된 방 사이의 왼쪽→오른쪽 상대 순서이며 실측 좌표가 아니다. 원래 교실, 비공개 교실, 강사용 공간도 포함해 공개수업과 구분한다.
- `source.classRow`와 `source.gradeRow`: 엑셀 근거 시트·행 번호. 공개수업에서 제외한 유치원은 수업 레코드를 생성하지 않는다.
- `gradeTheme`, `topic`, `designFocus`, `commonObservation`: 일반 학년 공통 수업에만 해당 학년 행을 연결한다. 6학년은 F열의 학급 대상을 구분하며 괄호 속 ‘6-1 영어 별도’는 공통 대상에서 제외한다.
- `context`, `observation`, `support`: 학급 행의 B/C/G열을 보존한다. 학년 공통 참관 포인트로 빈 학급 포인트를 채우지 않는다.
- `lenses`: D~F열에 실제 적힌 값만 순서대로 보존한다. 2개만 적혀 있으면 2개, 전부 비었으면 `[]`이다.
- 미제공 텍스트와 PDF ID는 `null`이다. 표시 문구를 데이터에 넣지 않는다. 텍스트는 `createMaterialText(value)`를 쓰고, `getLessonPlan(lesson)`이 `null`이면 `createPdfPlaceholder()`를 쓴다. 공통 컴포넌트는 `src/components/placeholders.ts`에 있다.

학급 중복·누락·알 수 없는 학급, 잘못된 렌즈, 애매한 여러 주제, 수식 셀 등은 확인 없이 처리하지 않고 변환을 중단한다. 같은 양식의 새 엑셀도 [결정 기록](<결정 기록.md>)과 충돌하면 규칙과 원문을 확인한다.
