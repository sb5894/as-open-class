## PDF 근거와 검증 한계

[PDF.js 공식 지원 설명](https://github.com/mozilla/pdf.js/wiki/Frequently-Asked-Questions#which-browsersenvironments-are-supported)은 현대 기능을 전제로 한 빌드와 호환 빌드를 구분한다. 설치된 6.4.299의 legacy 코드에도 Promise.withResolvers 호출이 남아 있음을 직접 확인했다. 수정 전 해당 API를 제거한 환경은 오류 안내를 표시했고, 수정 후에는 메인·worker 양쪽에서 API가 없는 상황의 페이지 렌더링 검사가 통과했다. 이것이 사용자 휴대폰 오류의 유일한 원인이라고 단정하지 않는다.

## 전반적인 버그 검토

- 단위 60항목 통과. 시간 변환의 한국 날짜 경계, 기존 입력·저장 실패·선택지·수업/공간 연결을 포함한다. 계단을 선 모양으로 바꾼 뒤 남아 있던 ‘계: 계단’ 범례도 ‘가로줄: 계단’으로 정정했다.
- 도면 모바일 검사 8항목 통과. 일반 모바일 검사 26항목 통과·외부 API opt-in 2항목 생략. 합계 34항목 통과이며 Chromium/WebKit 모의 검사다. 이후 추가한 위쪽 네 칸 동일 너비와 후관 2층 계단/E/V 비겹침 검사도 두 엔진에서 2항목 재확인해 통과했다.
- 타입 검사·웹/서버 빌드 통과. 빌드 결과를 4173 포트에서 두 엔진으로 열어 주요 8개 경로·없는 경로 안내·가로 넘침·내장 PDF worker·선택 강조 순서·미처리 JavaScript 오류 없음 확인.
- 원본 12개 크기·SHA-256 보존 확인. 신청 제출은 모두 모의 응답/테스트 저장 어댑터로 처리했으며 실제 시트 행은 추가하지 않았다.
- 별도 기능이나 구조 재작성은 하지 않았다. PDF 호환 보조 파일 두 개는 main/worker에서 동일한 누락 API를 보완하는 데만 사용한다.

## 질문에 대한 검토

**시트 열 숨김:** 가능하다. 코드는 시트 A:I에 RAW 값 9개를 append하며 숨김 여부를 읽거나 변경하지 않는다. B열 접수 ID·C열 구분 등을 숨겨도 저장 구조는 유지된다. 열을 삭제하거나 다른 순서로 옮기는 것은 다른 작업이며 현재 코드의 열 순서와 맞아야 한다. 이번에 실제 시트 표시 설정은 변경하지 않았다.

**길찾기:** 사용자 답변 ‘다음에’로 이번 작업에서 제외했다. 현재 도면은 수업·방 위치 자료이며 검증된 이동 경로망은 없다. 추후 실제 출입구, 건물 연결 통로, 사용할 계단·E/V, 통행 가능 구간을 확인한 뒤 별도 범위로 구현한다. 문서의 주차장→6-3 예시를 다른 모든 교실의 확정 경로로 확장하지 않았다.

**디자인·폰트 고민:** 구체적인 변경 지시가 없어 기존 디자인·시스템 글꼴을 유지했다. 요청한 메인 배치와 도면 모양 외의 전반적인 재디자인은 하지 않았다.
