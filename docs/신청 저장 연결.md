## 이번 피드백의 신청 저장 계약

- 2026-10-20 후속: 새 행의 I열 희망수업 표시는 장소 접미부 없이 저장한다. 예: `3-1 과학 · 본관 2층 1과학실` → `3-1 과학`. 학년 표시/H열 ID와 기존 행은 유지한다.
- 내부 키 `assignment`와 F열 위치는 유지하며 표시와 의미를 **직위**로 변경한다.
- `consent`는 boolean `true`여야 접수한다. 누락·미동의·문자열 값은 거절한다. J열에는 `동의`를 저장한다.
- 선택 입력 `question`은 생략 시 빈 문자열이다. 최대 2000자이며 탭·CR/LF 개행을 허용하고 나머지 C0/C1 제어문자는 거절한다. K열에는 원문 문자열을 RAW로 저장한다.
- 신규 행은 A:K 11칸을 저장한다. 기존 A:I 열 위치와 기존 행은 유지한다. 시트 헤더의 F1은 직위로 바꾸고 J1 `동의 여부`, K1 `문의 내용`을 추가해야 한다. API는 기존 행이나 헤더를 자동 변경하지 않는다.
- 이 변경은 로컬 구현이며 배포·실제 시트 변경·실제 저장 확인과 구분한다.

## 연결 순서

1. 사용할 프로젝트와 시트를 정한다. 프로젝트 ID를 정한 다음 `npm.cmd run firebase -- use --add`로 기본 프로젝트를 선택한다. `.firebaserc`는 로컬 설정이며 Git 제외 대상이다.
2. 선택한 프로젝트의 [Google Cloud API 라이브러리](https://console.cloud.google.com/apis/library/sheets.googleapis.com)에서 **Google Sheets API**를 사용 설정한다.
3. 저장할 탭을 만들고 첫 행 A1:K1에 다음 11개 제목을 순서대로 넣는다. 이 단계는 사용자가 지정한 시트에서 진행한다. API는 헤더나 탭을 자동 생성하지 않는다.

```text
제출시각	접수ID	구분	지역	소속교	직위	이름	희망수업ID	희망수업표시	동의 여부	문의 내용
```

4. 함수가 실행될 계정에 시트를 **편집자**로 공유한다. 권장 구성은 Cloud Console → IAM 및 관리자 → 서비스 계정에서 행사 전용 계정을 만들고 그 이메일을 공유하는 것이다. 이 용도로 서비스 계정 JSON 키를 만들 필요는 없다. 전용 계정을 쓰면 아래 `REGISTRATIONS_SERVICE_ACCOUNT`에 이메일을 설정하고 배포 계정에 그 서비스 계정을 사용할 권한이 있어야 한다. 비우면 Firebase 기본 실행 계정을 사용하며, 배포된 함수 설정에서 실제 계정 이메일을 확인해 공유한다. 프로젝트 전체에 Sheets 데이터 접근 권한을 주는 방식이 아니라 해당 시트를 공유하는 방식이다.
5. `functions/.env.example`을 참고해 **functions/.env.<프로젝트ID>**를 만든다. 실제 값은 Git 제외되며 브라우저 코드로 보내지 않는다.

```dotenv
SHEETS_SPREADSHEET_ID=시트주소에서확인한ID
SHEETS_TAB_NAME=registrations
REGISTRATIONS_SERVICE_ACCOUNT=직접만든계정@프로젝트ID.iam.gserviceaccount.com
```

6. 루트 `.env.local`에는 공개 프로젝트 ID 하나만 넣는다. `FIREBASE_PROJECT_ID=실제프로젝트ID`. Sheets ID·탭·키는 루트나 `VITE_` 변수에 넣지 않는다.
7. `npm.cmd run build` 후 함수 배포는 `npm.cmd run firebase -- deploy --only functions:registrations --project 실제프로젝트ID`로 한다. `as-open-class`에는 2026-10-18 사용자 승인 후 함수만 배포 완료했다. 전체 사이트 검토용 배포는 이후 8단계다.
8. 배포 출력의 함수 주소로 시험 신청을 보내고 실제 시트 행을 확인한다. 시험 신청도 실제 저장하며 C열에 **시험**으로 구분한다. 1개 선택·2개 선택 두 경우의 접수 ID가 시트 B열에 나타나는지 확인한다. 담당자는 집계할 때 시험 행을 제외한다.

서버는 [Application Default Credentials](https://cloud.google.com/docs/authentication/application-default-credentials)로 함수 실행 계정을 사용한다. 로그인 토큰이나 서비스 계정 키를 소스에 넣지 않는다. [Firebase 서버 환경변수](https://firebase.google.com/docs/functions/config-env), [함수 실행 계정](https://firebase.google.com/docs/reference/functions/2nd-gen/node/firebase-functions.globaloptions#globaloptionsserviceaccount), [시트 공유와 서비스 계정](https://developers.google.com/workspace/guides/create-credentials#service-account)

## 로컬 개발

프로젝트 미지정 상태의 오류 처리는 데모 프로젝트로 확인할 수 있다. 실제 시트에 접속하지 않으며 정상 입력에 `503 NOT_CONFIGURED`가 나오는 것이 맞다.

```powershell
npm.cmd run emulators -- --project demo-as-open-class
```

다른 터미널에서 `npm.cmd run dev`를 실행한다. 기존 개발 서버를 계속 켜 두었다면 새 `vite.config.ts`를 읽도록 한 번 재시작한다.

- Vite: `http://127.0.0.1:5173/api/registrations`
- Hosting 에뮬레이터: `http://127.0.0.1:5000/api/registrations`
- Functions 에뮬레이터: `http://127.0.0.1:5001/demo-as-open-class/asia-northeast3/registrations/api/registrations`

세 주소가 같은 `registrations` 함수로 연결된다. Hosting의 `/api/**` rewrite는 SPA rewrite보다 앞에 있다. Vite도 `/api` 요청을 함수로 프록시한다. `demo-` 프로젝트 또는 루트 `REGISTRATIONS_EMULATOR=true`이면 위 에뮬레이터로, 실제 프로젝트이면 배포된 서울 리전 함수로 연결한다. Vite preview도 같은 설정을 사용한다. 알 수 없는 API 주소는 HTML 화면으로 바꾸지 않고 404로 거부한다.

실제 프로젝트로 에뮬레이터를 사용하면 루트 `.env.local`의 프로젝트 ID와 `--project`를 같게 한다. 함수 설정은 `functions/.env.local`로 덮어쓸 수 있다. 로컬에서 실제 Sheets 저장까지 하려면 Sheets 권한이 있는 ADC가 별도로 필요하다. Firebase CLI 로그인만으로는 충분하지 않다. 기존 ADC나 로컬 인증 설정이 없다면 서버를 배포해 함수 실행 계정으로 확인하는 편이 간단하다. `GOOGLE_APPLICATION_CREDENTIALS`를 쓰는 경우에도 파일은 개인 로컬 위치에 두고 키 내용은 공유하지 않는다.

## 실제 시트까지 자동 확인하는 도구

`scripts/verify-registration-live.mjs`는 실제 API에 **시험 신청 2개를 추가**하고, ADC로 지정한 시트에서 접수 ID와 행 내용을 다시 읽어 일치하는지 확인한다. 읽기 권한/헤더를 먼저 확인하며, 그 확인이 실패하면 시험 신청을 보내지 않는다. 자동으로 재제출하지 않는다.

```powershell
npm.cmd run verify:registration -- --url "배포출력의함수주소" --sheet-id "실제시트ID" --tab "registrations"
```

이 도구를 실행하는 PC에는 해당 시트를 읽을 수 있고 `spreadsheets.readonly` 범위로 인증 가능한 ADC가 필요하다. 이는 서버 함수 실행 계정의 인증과 별개다. 도구에서 읽기 인증을 준비하기 어렵다면 시험 API 응답의 접수 ID를 사용해 시트에서 직접 확인한 뒤 결과를 기록한다. 이번 3-E는 로컬 ADC가 없어 이 도구 대신 일회용 요청과 지정 탭의 CSV 재조회로 두 행을 검증했다. 이 도구를 지금 실행하면 시험 두 건이 추가되므로 재실행하지 않는다. 검증을 위해 시트를 새로 공개할 필요는 없다.

## API 계약

### localhost 연결·시각 표기 최신 상태 — 2026-10-19

- localhost에서도 Vite의 `/api` 프록시가 실제 Firebase 함수로 연결되므로 신청할 수 있다. 5173(dev)·4173(preview)에서 확인한 502는 기존 서버 프로세스의 외부 통신 차단 `EACCES` 때문이었다. 두 서버를 네트워크가 허용된 환경에서 다시 시작했고 현재 빈 입력에 Firebase HTTP 400이 정상 반환된다. 새 정상 신청은 전송하지 않아 새 시트 행은 추가하지 않았다.
- 시트 A열은 서버가 한국 시간 `YYYY-MM-DD HH:mm` 문자열로 저장하도록 로컬 코드를 수정했다. 시트 메뉴에서 사용자가 바꿀 설정은 없다. 2026-10-19 운영 함수 재배포를 완료해 새 저장 행에 적용된다. 기존 행은 자동 변환하지 않는다. API 응답의 ISO 시각과 A:I 기존 9개 열 위치는 유지한다. F열 의미는 직위로 바꾸고 J열 동의 여부, K열 문의 내용을 덧붙인다. 기존 행은 수정하지 않는다.

`POST /api/registrations`, `Content-Type: application/json`

```json
{
  "city": "안성시",
  "school": "소속교",
  "assignment": "교사",
  "name": "신청자 이름",
  "lessonIds": ["lesson-3-1", "lesson-4-5"],
  "consent": true,
  "question": "문의 내용 (선택)",
  "isTest": false
}
```

지역·소속교·직위·이름은 비어 있지 않은 한 줄 문자열이다. 앞뒤 공백을 정리하고 각각 80·120·120·80자까지 받는다. 관심있는 수업은 **선택 사항**으로, `lessonIds: []` 또는 학년·별도 수업 선택지 ID 중 서로 다른 최대 2개다. 일반 학년은 `grade-1`~`grade-6`, 수석교사·전담·다문화는 기존 해당 수업 ID를 사용하며 유치원은 제외한다. 학년 선택은 학급 ID 여러 개로 확장하지 않으며 H열에는 선택 ID, I열에는 학년 이름을 저장한다. 공개수업인 이전 학급 ID도 호환성을 위해 계속 받는다. 화면과 서버가 `functions/src/interest-options.ts`를 공유한다. 배열 필드는 항상 전송하며 미선택 시 시트 H·I열을 빈 값으로 기록한다. 3개 이상·중복·유치원·5-1·강사용 교실·알 수 없는 ID는 거부한다. 순위는 없으며 ID/표시 이름은 공개 목록 순서로 기록한다. 같은 사람이 다시 제출하면 새 접수 ID로 한 행을 더 저장한다. `isTest`는 생략 시 false이며 저장을 건너뛰는 옵션이 아니다.

| 상태 | 응답과 화면 처리 |
|---|---|
| 201 | `ok: true`, `status: saved`, `registrationId`, `submittedAt`. Sheets가 11칸 한 행의 저장을 확인한 뒤에만 반환 |
| 400 | `INVALID_INPUT`, `fieldErrors`. 입력을 유지하고 해당 필드를 수정하도록 안내 |
| 503 | `NOT_CONFIGURED` 또는 `SAVE_NOT_CONFIRMED`, `retryable: true`. 완료 화면을 띄우지 않고 입력 유지·재시도 |
| 405/404/415/413 | 지원하지 않는 메서드/주소/형식/너무 큰 입력 |

응답에는 신청자 입력값·시트 ID·인증 정보가 들어가지 않는다. 오류 로그도 고정된 오류 종류와 접수 ID만 남긴다. Sheets에는 [values.append](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/append)의 `RAW` 방식으로 저장해 `=` 등으로 시작한 문자열도 수식으로 실행하지 않는다. 서버의 append 요청은 자동 재시도를 끈다. 네트워크가 끊긴 경우 시트에 저장됐지만 응답을 못 받았을 수 있으므로 성공으로 표시하지 않으며, 사용자의 수동 재시도로 생긴 중복은 담당자가 정리한다.

4단계 화면은 `src/registrations/client.ts`의 제출 상태를 사용한다. `submitting` 동안 버튼을 잠그며 동시에 들어온 제출은 추가 요청을 보내지 않는다. 실패하면 `input` 스냅샷과 오류 응답을 유지하고 잠금을 풀며 자동 재전송하지 않는다. 4단계에서 실제 `/register` 신청 화면을 연결했다. 4단계 인터페이스 수정 후 미선택 제출을 실제 서버·시트에서 추가 검증했다. 시험 접수 번호 `058fce8f-926d-4fd7-88dd-377d8de91ed6`의 HTTP 201·H/I 빈 값·동일 브라우저의 PDF 이동까지 확인했다. 반복 실행하지 않으며 상세 증거는 진행 현황에 있다.




## 수정 2 실제 학년·전담 저장 검증

기존 함수를 업데이트한 뒤 모바일 크기 화면에서 `1학년 + 과학 전담(4학년)` 시험 신청 1건을 전송했다. HTTP 201, 접수 번호 `d9bd6188-73a6-4d57-b716-290a4365bcf5`를 시트에서 조회해 H열 `grade-1 / lesson-4-5`, I열 `1학년 / 4-5 과학 · 본관 2층 2과학실`을 직접 확인했다. 같은 브라우저의 둘러보기→PDF까지 검증했다. 재전송하지 않으며 자세한 증거는 진행 현황에 있다. 기존 시트 헤더는 호환성을 위해 유지한다.
